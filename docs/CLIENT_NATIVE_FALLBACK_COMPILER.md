# Native APT/DNF fallback proposal compiler — issue #24

**Status:** Stage-A source implementation, not a privileged helper, installed
feature, or native/SELinux acceptance. The scriptable client still refuses
`repos sync --apply` until a separately reviewed installed transaction and
the final host evidence exist.

## What the compiler guarantees

`client/native_fallback_plan.py` takes a strict source file baseline SHA-256,
selected repository-entry SHA-256, a stable managed ID, the exact original
upstream and the proposed HTTPS cache endpoint. It emits a byte-exact source
proposal and (for APT) one managed mirrorlist companion. It does **not** read,
write, execute, fetch a catalog or authenticate the caller. Its output declares
`production_write_eligible=False`, `route_approval_verified=False` and
`native_fallback_verified=False`.

- **Debian 13 APT:** For an existing enabled, one-URL `.list` or deb822
  `.sources` entry with an explicit `signed-by`/`Signed-By` keyring,
  preserve every other byte (including unrelated repositories and signing
  options). Substitute only the URL with
  `mirror+file:/etc/apt/mirrors/repocache-<managed-id>.list`; propose a
  root-owned companion with the validated HTTPS cache at `priority:1` and
  original HTTPS upstream at `priority:2`. Debian's mirror transport retries
  another mirror when acquisition fails; order without priorities is not
  deterministic. The file is **not** created automatically.
- **AlmaLinux 10 DNF5:** For an enabled one-baseurl `.repo` section that
  already requires `gpgcheck=1`, `repo_gpgcheck=1` and a local
  `file:///etc/pki/rpm-gpg/...` key, preserve all other source bytes.
  Propose the documented ordered `baseurl=<cache> <upstream>` list. Do not
  generate or import signing keys, alter metadata/package verification or
  widen network exposure.
- **Every proposal:** Reject credentials, malformed/noncanonical HTTPS URLs,
  unknown/duplicate target entries, unsafe source paths, changed baselines,
  unsigned/mirrorlist sources and ambiguous shared-file boundaries. Siblings
  in mixed files are preserved byte-for-byte. The compiler is never imported
  by the installed CLI or installer.

The supported subset is intentionally conservative. In particular, external
APT mirrorlists and DNF metalinks, multiple existing URLs, unapproved keyring
locations and legacy unsigned RPM metadata are **not eligible** for this
compiler; keep these repositories direct until native fallback and signing
evidence are established. `gpgcheck=1` alone does not prove RPM metadata
signing.

## Missing production trust gates (still NOT VERIFIED)

1. Authenticate the **actual active** server-side catalog (#28/#95) over
   verified TLS; bind exact server origin, upstream, cache route and fresh
   administrator route approval (UC-45). A caller-supplied URL or digest is
   never root authorization.
2. Establish protected ownership and a unique per-entry/file registry, one
   exclusive root-owned transaction lock, package-manager lock checks,
   symlink/hardlink and native metadata/SELinux checks.
3. Install the APT companion and source changes as a **multi-resource atomic
   and recoverable transaction**. A crash after companion creation but before
   source replacement, or the reverse during rollback, must not leave a
   broken source. Safely preserve only the original and previous known-good
   versions, ACLs, xattrs, TLS certificate policy and unrelated entries.
4. Test and confirm strict native APT/DNF syntax, signed metadata **and
   package payloads**, preferred cache, cache outage/upstream fallback and
   recovery on actual binaries; reject an unsafe target with no write.
5. Integrate fixed root-helper validation/commit/recovery/restore with
   `repocache-client repos sync --apply` only after the preceding gates.
   Record native booted Debian 13 and AlmaLinux 10 (SELinux enforcing)
   acceptance in the final #19 VM campaign; do not claim it from containers.

CI unit tests for this proposal are in
`tests/test_client_native_fallback_plan.py`. The preexisting
`scripts/ci_client_native_fallback.py` tests the *native mechanisms* with
ephemeral signatures, network servers and packages in disposable distribution
containers. They do not prove production source approval/atomic installation.
The generated byte format must also be tested with native managers before any
writer is enabled.

## Fixed package-manager lock observation prerequisite

`client/native_package_lock_observation.py` provides an additional
**read-only** Linux `/proc/locks` snapshot against fixed APT/dpkg lock
inodes and candidate DNF5/RPM lock inodes. It refuses malformed tables,
non-regular, symlinked or multi-linked leaf files and reports missing
native lock files as `NOT_VERIFIED`. Even when no lock is observed, the
result is only `OBSERVED_UNCONTENDED`: it **never** holds an exclusive
lock, prevents a new package-manager process, or authorizes source edits.
The root writer must independently obtain a durable exclusive lock, prove
actual native manager exclusion at the commit boundary and fail closed
on races. Test evidence: `tests/test_client_native_package_lock_observation.py`.
