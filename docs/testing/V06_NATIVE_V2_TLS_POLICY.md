# Native v2 transaction: shared TLS security policy (#31 / #30)

The fixed-path, durable native v2 NGINX/state/catalog transaction in #237
now consumes the **same** strict TLS listener candidate renderer as the
source-only #30 TLS diagnostics, instead of maintaining a second independent
set of SSL directives.

This closes a configuration-policy gap: the former private include manually
emitted a TLS listener, host and certificate/key, but did not explicitly
require \`ssl_protocols TLSv1.2 TLSv1.3\`, \`ssl_session_tickets off\` and
\`server_tokens off\`. The fixed candidate now includes those directives
exactly once while retaining the generation health endpoint, versioned
read-only catalog path and all currently active pinned repository routes.

The native transaction **must still independently verify** the genuine
operator-provided leaf/key pair, host CA trust, NGINX unit and binary
ownership, root-owned state and private controller, full-context syntax,
native worker reload, live HTTPS exposure, and durable rollback across the
included resources. A pure candidate is never a proof of these properties.
Untrusted candidate authority booleans or invalid TLS inputs refuse
before the first WAL or public include write. Existing fixture tests assert
no partial state/catalog and full TLS policy on generated bytes.

**Stage A:** existing unit and disposable NGINX syntax tests, including
negative altered-renderer authority and repeated native-v2 transaction
cases. **Stage B/C NOT VERIFIED:** a signed installed server on booted
Debian 13 and AlmaLinux 10 with systemd, enforcing SELinux, external
certificate trust and the separately commissioned #64 security review
plus explicit issue-specific merger approval. PR #237 remains Draft and
not eligible for the native integration queue until all its blocking gates
are resolved.
